# 共同随机数耦合评测：玩具模型上的初步验证

这个实验检验报告中选题 E（用共同随机数耦合多步智能体的 A/B 评测）的核心机制。当前环境没有 GPU，也没有可用于实验的 LLM API，所以先用可控的模拟回答两个问题：

1. 两个配置共享随机性时，成功率差值估计的方差能降多少？
2. 共享的随机数要怎样对齐，才能在轨迹分叉后仍然有效？

结论只针对玩具模型的机制。真实 LLM 智能体上的收益大小仍需实测，见文末的下一步。

## 设定

- **任务**：一个任务有 K 个子目标，步数预算为 2K+2。每一步对当前子目标做一次 Gumbel-max 决策，共 5 个动作：
  - 1 个正确动作；
  - 3 个无害错误，下一步重试；
  - 1 个不可逆错误，直接判失败。
- **环境噪声**：工具以概率 f 失败。
- **推理 token**：每次决策前先产生 1–2 个推理 token。它们消耗随机数，但不影响结果。
- **任务难度**：各任务、各子目标的难度不同，由正确动作的 logit 随机偏移体现。
- **两个配置**：B 在 A 的基础上把正确动作的 logit 加 δ（定向改进），并对所有 logit 加一个固定扰动 N(0, σ²)，模拟改 prompt 带来的副作用。
- **四种噪声方案**：

  | 方案 | 做法 |
  |---|---|
  | indep | 两组各用独立随机数，即现在的通常做法 |
  | same_seed | 两组按顺序读同一条随机数流，相当于给采样器传同一个 seed；环境按步数设同一个 seed |
  | event | 每个随机数按它决定的事来索引：策略噪声用（任务，运行，子目标，第几次尝试，动作），环境噪声用（任务，运行，子目标，第几次尝试） |
  | event_policy | 策略噪声按事件对齐，环境噪声各自独立 |

  same_seed_verbose_b 与 same_seed 相同，只是 B 每次决策多产生一个推理 token 的概率高 10 个百分点（0.6 对 0.5）。

- **指标**：
  - **VRF**：独立采样下 Var(S_B−S_A) 与耦合方案下 Var(S_B−S_A) 之比。它等于达到同样统计功效时所需运行次数的缩减倍数。
  - **反转率**：P(S_B < S_A)，即同一份随机性下 B 失败而 A 成功的比例。
  - **每组所需运行数**：在 80% 功效、双侧 α=0.05 下所需的运行次数。
- **规模**：100 个任务，每个任务每组 2000 次运行。所有方案的 Δ̂ 在蒙特卡洛误差内一致，无偏性检查通过，见 `results.txt`。

## 初步结论

1. **耦合有效，估计也无偏。** 在常见设定下，按事件对齐的耦合把达到同样统计功效所需的运行数降到 1/3 到 1/6；改动小而定向时降到 1/30 以上。
2. **"同一个 seed"这种常见做法很脆弱，随机数必须按事件对齐。**
   - 轨迹一旦分叉，按位置读取的随机数就会对应到语义不同的决策上，same_seed 的收益随轨迹变长而流失：K=40 时只剩 event 的 63%。
   - 只要 B 的输出长度和 A 稍有不同（多一个推理 token 的概率高 10 个百分点），随机数流就会错位。在 K=10–40 时收益塌缩到 1.2–1.9 倍，同等条件下 event 为 3.5–5.9 倍。
   - 真实 LLM 改了 prompt 后输出长度几乎必然改变，所以噪声的索引必须是结构化的，例如（轮次，工具调用，参数槽位，token 偏移），不能用全局位置。
3. **环境的随机性也必须一起耦合。** 只耦合策略采样（单轮耦合工作的做法）时，工具失败率为 0.3 的环境里收益从 5.3 倍掉到 2.1 倍。用户模拟器和评判模型同理。这正是相对单轮耦合工作的新意所在。
4. **收益取决于改动有多"定向"，反转率可以当作诊断指标。**
   - 若 B 只抬高正确动作的 logit，事件对齐下结果逐路径单调：D ∈ {0, 1}，从不反转。于是 Var(D) = Δ(1−Δ)，所需样本量从随 1/Δ² 增长变为随 1/Δ 增长，效应越小，收益越大。
   - 宽泛改动会引入反转，收益封顶在 5 倍左右（σ=0.25）或更低。
   - 可以写成一个命题：Gumbel-max 结构因果模型具有反事实稳定性，加上事件对齐，就得到单调性。
   - 实验中反转率可以直接测出，用来预测某次改动能省多少运行，也能标出"同样的运气下新配置反而更差"的具体任务，这是调试信号。

## 局限

- 玩具模型的决策是语义固定的离散动作。真实 LLM 的决策是 token 序列，事件键只能在轮次或工具调用的边界重新对齐，同一段自由文本推理内部一旦分叉就对不齐。所以真实收益应落在 same_seed_verbose_b 和 event 之间，具体位置是论文要实测的核心问题。
- 只适用于共享词表的配置比较，例如不同 prompt、不同脚手架、解码参数、同一基座的微调版本。不同 tokenizer 的模型无法做 token 级耦合。
- 需要逐位确定的推理：串行、batch=1、关闭前缀缓存，或者用 vLLM 的 batch invariance（目前为 beta）。闭源 API 只能传 seed，这正是结论 2 里脆弱的那种情形。
- 这里的定向改进与宽泛改动是人为参数化的，真实的 prompt 改动落在谱上的哪个位置需要测量。
- 对"整体 Δ"的评测，CRN 是无偏的。但把 CRN 用于逐步归因时，2609.06445 指出的估计量问题依然存在，写论文时要正面回应。

## 下一步：在真实 LLM 智能体上验证

1. 在 vLLM 里实现按事件索引的 Gumbel 采样器：对（任务，运行，轮次，工具调用，token 偏移，词表 id）做计数器式哈希，在 GPU 上向量化生成噪声。同时关闭前缀缓存，或开启 batch invariance。
2. 选可设种子的环境，把用户模拟器 LLM 也纳入耦合：τ²-bench、AppWorld、ALFWorld、TextCraft 等。
3. 比较几类配置：定向与宽泛的 prompt 改动、脚手架改动、温度、同一基座的微调版本。测量 VRF、反转率、达到显著所需的运行数，并重新检验若干已发表的 A/B 结论。
4. 理论部分：
   - 证明单调耦合的命题；
   - 分析对齐失效的条件；
   - 做方差分量分解，区分哪些方差成分可以被耦合消除，哪些不行（如 harness、基础设施、服务提供方）。

一张能跑 7–8B 开源模型的 GPU 足够起步。

## 复现

```bash
pip install numpy
python sim.py --tasks 100 --runs 2000 --out results.json   # 4 核 CPU 约 2 分钟
```

`results.json` 是完整结果，`results.txt` 是控制台输出，包含无偏性检查和反转率。
